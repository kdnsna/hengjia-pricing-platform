# 全产品计价系统

面向银行全员全产品计价的全栈工作台。内置用户提供的 2026 年计价标准 51 项，其中利润类 20 项、规模类 11 项、客户类 20 项；个金 27 项保留明确提供的 M 码关联。

## 功能

- 六类岗位工作台：普通员工、客户经理、机构负责人、分行领导、复核人员和计价管理员。
- 权限与数据范围：菜单、操作按钮、服务端接口及本人／本机构／全行数据范围同步控制。
- 计价规则：搜索筛选、单价与算法查看、取数关联和清单导出；正式规则不能直接修改。
- 指标设计：五种算法、公式、考核细则、四组场景测试、提交复核、独立复测、发布和历史版本。
- 计价试算：直接计价、存量逐月、时间加权、季度折算、封顶保底、正负增与零值处理。
- 业绩归属：本机构多人分润、本人参与约束、依据留痕、比例合计校验及归属人本人确认。
- 批次管理：服务端复算、完整明细与规则快照、退回原因、草稿编辑重算、重新提交、独立审批锁定、操作日志及明细导出。
- 期间与统计：分润和批次按所选期间过滤，工作台积分只汇总已锁定批次。
- 建设方案：功能清单、分层设计、办理流程、建设步骤及外部系统边界。

## 技术栈

React 19、TypeScript、Vite、Tailwind CSS、Hono、tRPC、Drizzle ORM、MySQL。

## 本地运行

```bash
npm ci
```

根据 `.env.example` 配置自己的 `.env`，真实凭据不得提交到仓库。然后执行：

```bash
npm run db:push
npm run dev
```

开发服务默认端口为 `3000`。

## 检查与生产运行

```bash
npm run check
npm test
npm run lint
npm run build
npm start
```

生产入口为 `dist/boot.js`，前端入口为 `dist/public/index.html`。部署包必须包含构建后的依赖 bundle，不能依赖开发目录中的 `node_modules`。

## 验收

- `verifier/v1/`：计算规则、业务完整性和基础页面验收。
- `verifier/v2/`：指标设计、公式、测试、复核发布和版本验收。
- `verifier/v3/`：建设方案、功能差距和规划边界验收。
- `verifier/v4/`：六类账号、数据范围、职责分离、响应式、数据库约束及隔离生产冷启动验收。
- `verifier/v5/`：产品名称、批次明细与退回、本人分润确认、期间筛选和锁定积分口径验收。

验收结果与桌面／移动端截图保存在 `verifier/runs/`。接口和浏览器脚本默认访问 `http://localhost:3000`，也可通过 `VERIFY_ORIGIN` 指定独立验收地址。浏览器脚本默认使用 `/usr/bin/chromium`，本机路径不同时可通过 `CHROME_PATH` 指定。

## 数据与边界

数据通过 tRPC 与 Drizzle 持久化到 MySQL。当前人员、机构积分及批次数字为演示数据；年度单价来自用户提供的扫描件。

本人分润确认只表示员工核对归属比例和依据，不等于薪酬审批、完整绩效结果发布或放弃异议权利。当前为本地演示账号体系，不是银行统一身份认证。核心业务、人力资源、薪酬支付、完整员工申诉和监管报送等外部系统或流程尚未连接；规划能力不作为已交付生产功能。
