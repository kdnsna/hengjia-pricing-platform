# V2 验收标准：指标设计中心

日期：2026-10-25。V2 在保留 V1 全部标准的基础上新增以下标准，不覆盖或改写 V1 及其运行记录。

## 设计完整性
- 可新增指标，也可基于正式指标创建新版；指标编码、责任边界、业务定义、源系统、取数 M 码、积分 M 码、源单位与换算除数均可配置。
- 支持直接计价、存量逐月、时间加权、季度日均、自定义公式五种方式，以及存量、正增、负增单价。
- 考核细则覆盖周期、目标、权重、封顶、保底、精度、舍入、适用机构与岗位、归属、负积分、凭证、生效期间、复核流程、计提说明、排除项、冲正与补录。
- 正式规则与设计稿隔离；未发布设计不得进入正式试算，既有指标新版发布前不得影响当前正式版。

## 公式与计算安全
- 公式仅允许白名单变量、IF/MIN/MAX/ROUND/ABS、四则、比较、逻辑和条件运算；不得执行对象访问、动态脚本或任意函数。
- 未知变量、非法结构、除零、非有限结果必须被识别；IF 与条件分支只计算命中分支。
- 源单位为元时，公式必须使用 UNIT_FACTOR 或显式除以 10000；时间加权公式必须引用 MONTH。
- 正向、负向、零值、一月进度四组标准场景均通过后才可提交；提交与发布均由服务端重新校验和测试。
- 预置算法转换为显式公式后，同样输入的计算结果保持一致。

## 生命周期与追溯
- 草稿可保存并在刷新后继续编辑；草稿提交后进入待复核，只有待复核设计可发布。
- 发布生成 baseVersion+1 的正式版本，公式、单价和考核细则形成同版快照；发布不得覆盖历史设计或既有试算批次。
- 版本冲突、重复编码、重复未发布设计、修改已发布/已归档设计必须被服务端阻断。
- 归档设计仍可查询，且从未发布的新指标归档后不得出现在正式规则库。
- 正式指标可停用和重新启用；停用后退出新试算，历史记录保留。

## 真实端到端
- 在生产服务中实际完成：新建 → 保存草稿 → 非法公式/除零测试 → 修复 → 四组测试 → 提交复核 → 发布 V1 → 正式试算。
- 实际完成：创建 V2 草稿 → 验证 V1 仍有效 → 发布 V2 → 验证新结果 → 查询两个发布快照。
- 实际完成：另建草稿并归档；正式指标停用、重新启用、再停用；试算批次保存规则版本与完整定义快照。
- 验收演练指标必须明确标注“设计演练”，最终保持停用，不冒充年度权威指标。

## 工程质量
- TypeScript 检查、生产构建、公式引擎、后端接口及浏览器验收均零未处理失败。
- 使用 dist/boot.js 与 dist/public/index.html 冷启动验证；数据库读写真实成功。
- 1440、1024、768、375 像素关键视图无页面横向溢出；375 像素主要按钮触控高度不小于 44 像素。
- 浏览器无未预期控制台错误、页面异常或资源 404；预期被阻断的业务请求须单独记录，不能混入“无失败响应”结论。
- 关键页面、编辑器、测试、发布、版本记录和移动端截图须人工查看。

## 边界
- 取数字段是可维护映射，不代表已连接核心生产系统。
- 演练单价仅用于验证计算，不是对年度计价制度的补充或修改。
