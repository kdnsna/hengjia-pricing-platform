# V4 验收标准：六类账号、数据范围与职责分离

日期：2026-10-26。V4 保留 V1—V3 的指标、公式、试算、归属、批次、版本和建设方案验收要求，新增真实登录、岗位权限和实用化表达检查。历史验收文件及运行记录不覆盖。

## 登录与会话

- 普通员工、客户经理、机构负责人、分行领导、复核人员、计价管理员六类演示账号均可登录，角色和机构与共享权限定义一致。
- 未登录或会话无效时，业务接口返回 UNAUTHORIZED；退出后原会话不可再用。
- Cookie 使用 HttpOnly、SameSite=Lax 和 8 小时有效期；数据库只保存会话令牌哈希。过期会话不能访问业务接口。
- 错误密码有明确提示；同一账号连续失败 5 次后触发 15 分钟限流。该限流为单进程演示控制，不冒充分布式生产安全方案。
- 停用、角色或机构调整后，该账号原会话失效；停用账号不能重新登录。管理员不能修改自己的角色、机构或状态。

## 服务端权限与数据范围

- 普通员工和客户经理仅取得本人工作数据；机构负责人仅取得本机构人员、分润和批次；领导、复核人员和管理员按权限取得全行数据。
- 员工不能保存正式批次、维护指标、登记分润或管理账号；领导只读；复核人员不能修改规则或保存批次；管理员不能发布指标或审批批次。
- 权限必须落实在服务端接口，不以隐藏菜单或按钮代替。未授权直接调用接口必须返回 FORBIDDEN。
- 停用人员不能新增分润；分润人员姓名和机构以服务端目录为准。
- 客户经理只能登记本机构且本人参与的分润：须先登记本人记录，才能添加同一期间、同一产品的协同人员。
- 同一期间、同一产品的分润比例合计不得超过 100%；跨机构请求必须由服务端拦截。

## 指标设计与正式规则

- 保留五种算法、公式白名单、单位换算、零值与负积分边界、四组场景测试和历史版本。
- 正式单价和公式不能从规则页直接修改；只能通过“创建新版—测试—提交—独立复核—发布”变更。
- 待复核设计对管理员只读，不能通过保存操作隐式回到草稿；复核退回后才能继续编辑。
- 提交人不能发布或退回本人提交的指标；复核人员独立复测后可发布或退回。
- 已发布规则、设计状态、版本号和提交／发布人必须与接口及数据库记录一致。

## 批次办理与防篡改

- 保存批次时，服务端重新检查人员范围、规则状态、规则版本和计算结果。
- 篡改明细积分、总积分、计价人数或规则版本必须被拒绝；跨机构人员不能写入批次。
- 草稿提交与审批锁定分离；提交人不能审批本人提交的批次；已锁定批次不能重复提交或审批。
- 历史批次保留实际人员、规则版本、规则定义、输入、计算过程及结果快照。

## 实用化表达与建设边界

- 页面使用建设方案、功能清单、办理流程、计算规则等工作用语，移除“平台蓝图、计价引擎、全链路、端到端、智能化建议”等泛化表达。
- 建设方案同步反映六类角色和服务端权限的当前状态，不再保留“固定管理身份、未做权限”等旧说明。
- 历史公式核查按实际发现的问题展示，不宣称静态清单等同于生产全量自动校验。
- 明确本地演示账号不是银行统一身份认证；HR、SSO、MFA、核心业务、薪酬支付和监管报送未连接的能力不得标为已交付。

## 工程与页面验收

- TypeScript 检查、只读公式测试和生产构建通过；不得修改默认 build 脚本。
- 使用最新 `dist/boot.js` 与 `dist/public/index.html`，在不含 `node_modules` 的隔离目录冷启动并验证真实接口。隔离验收可通过 `PORT` 和 `VERIFY_ORIGIN` 指定独立端口，避免误连其他本地服务；应用默认端口仍保持 3000。
- 六类账号的关键页面均有真实浏览器操作证据；登录、退出、只读复核状态和权限差异至少各验证一次。
- 1440、1024、768、375 像素无页面横向溢出；375 像素主要操作按钮不小于 44px；桌面和移动截图须逐张查看。
- 无未预期控制台错误、页面异常、资源 404 或失败响应。
- 每次运行均在 `verifier/runs/` 追加时间戳、命令、退出码和结果；测试使用独立账号和指标，不清库、不删表、不删除既有业务数据。
